# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

RanjanSoft's company website is a **single self-contained `index.html`** (about 130 KB). It has no build step, framework, package manager, linter or tests. The CSS and JS are inline, so edit `index.html` directly.

## Run / preview

```bash
python3 -m http.server 8000                         # quickest local preview -> http://localhost:8000
podman-compose -f podman-compose.yml up -d --build  # nginx:1.27-alpine container on http://localhost:10105
podman-compose -f podman-compose.yml down
```

- `podman-compose.tml` is a stray duplicate with a typo in the extension. Use `podman-compose.yml`.
- `gen-self-signed-cert.sh` writes a local-only TLS cert into `certs/`. The Dockerfile serves plain HTTP on port 80 only.
- There is no CI workflow in the repo (`.github/` does not exist). Deployment means building the Dockerfile.

## Deploy constraint

The Dockerfile copies **only `index.html`** into the nginx web root. Any new local asset (image, favicon, CSS/JS file) needs a matching `COPY` line, or it must be inlined. For example, the favicon is an inline SVG data URI for this reason. External assets come from CDNs: Google Fonts (Syne, Outfit, JetBrains Mono) and devicon SVGs on jsDelivr.

## How `index.html` is organised

- **Design tokens** live at the top of `<style>`. There are two `:root` / `[data-theme="light"]` palette sets. The first (cyan, `#38BDF8`) is **commented out**. The active one is the second, purple set (`--cyan: #7C3AED` dark / `#6D28D9` light). The variable is still named `--cyan` even though it is now purple, so change colours through these tokens and not by hard-coding values.
- **Theming:** `<html data-theme="dark">` is the default. `toggleTheme()` flips the attribute. Nothing is persisted.
- **Pages:** it is a client-side "SPA" without routing or URLs. Each page is a `<div class="page" id="page-<name>">` (home, about, services, projects, contact). `goto('<name>')` toggles `.active` on the page and on nav links matched by `data-page="<name>"`. Nav exists twice, in the desktop `.nav-links` and the mobile `#mob-menu`, so a nav change has to be made in both. The Contact page markup exists but its nav links are commented out.
- **Scroll fade-in:** add class `fi` to an element. `initFI()` uses an IntersectionObserver to add `.vis`, and it re-runs after every `goto()`.
- **Counters:** `data-cnt="<number>"` plus an optional `data-sfx="+"` animate on load.
- **Projects:** each `.proj-card` carries `data-status="current|hold|delivered"`. `filterProj()` filters the cards, and `updateProjCounts()` fills the `#cnt-all/#cnt-curr/#cnt-hold/#cnt-done` badges automatically, so adding a card needs no count edits.
- **Tech stack tabs:** the second `<script>` turns each `.tech-category` label inside `#tech-panels-container` into a tab button. The grid that follows each label is the panel. The default tab is index 2 ("Backend & API"), so inserting or reordering categories shifts that default.

## Tooling noise

`.claude-flow/`, `.swarm/` and `ruvector.db` are generated by local agent tooling (ruflo). They are not part of the site, so don't edit them by hand. Some `.claude-flow/` files are already tracked, so leave their churn out of site commits. `deployment-ducument.*` are standalone docs, not served by the site.
